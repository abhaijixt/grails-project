# Writing Rules (Anti-AI Style Guide)

Read this before writing any wiki article or output. The goal: text that reads like a sharp human wrote it for their own reference.

## Never do these

- **Puffery and hype**: no "game-changing", "revolutionary", "powerful", "seamless", "delve", "unlock", "elevate", "supercharge", "in today's fast-paced world".
- **Empty summarizing closers**: no "In conclusion", "Overall", "Ultimately, it's up to you", "The possibilities are endless".
- **Rule-of-three padding**: avoid reflexive triplets ("faster, smarter, better") unless the three items each carry weight.
- **Hedging stacks**: one qualifier at most. Not "it could potentially perhaps help".
- **Symmetrical "not only X but also Y" constructions** as a default sentence shape.
- **Title Case Headers Everywhere** — sentence case for headers below H1.
- **Em-dash overuse** — at most one per paragraph.
- **Bold-term-colon-explanation lists** as the default format for everything; use prose when prose reads better.
- **Inflated significance**: don't call an idea "profound" or "crucial"; show why it matters in one concrete sentence instead.

## Always do these

- Cite the raw source file for every substantive claim in a wiki article.
- Prefer concrete numbers, commands, and file paths over abstractions.
- Short sentences over subordinate-clause chains.
- If two sources disagree, say so plainly and name both — don't average them.
- British or American spelling is fine; be consistent within one article.
